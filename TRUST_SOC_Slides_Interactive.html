Introduction: The SOC Alert Fatigue Crisis & Baseline Deficiencies
The Modern SOC Landscape
Frontline Cyber Defence: SOCs continuously monitor network flows, host telemetry, and endpoint logs to protect enterprise assets.
Event Ingestion Scale: Modern enterprises generate millions of events daily. Intrusion detection engines routinely flag thousands of raw alerts.
The 'Alert Fatigue' Bottleneck: Over 80–90% of alerts are false alarms. Analysts suffer severe cognitive overload, deprioritizing alerts and missing actual intrusions.
Failure of Standalone Classifiers: A single model evaluated on static benchmark data cannot be safely trusted: it lacks self-verification and provides zero auditability.
Key Deficiencies in Conventional IDS Research
1. No Second Line of Defence: Classifier errors reach the analyst unchecked. False alarms are passively measured, never filtered in-pipeline.
2. Opaque, Black-Box Verdicts: Categorical labels (e.g. 'DDoS') without feature attribution; analysts cannot discern why an alert triggered.
3. Absent Audit Trail: Alerts are disconnected from raw network logs, feature vectors, and corroboration rationale, impeding compliance review.
4. Uniform Urgency: Without multi-source confidence fusion, analysts must treat every notification with equal urgency.

Introduction: The TRUST-SOC Multi-Agent Solution
The TRUST-SOC Paradigm: Decomposing SOC Triage into Cooperating Agents

Instead of a monolithic model, TRUST-SOC implements a detect-then-verify multi-agent architecture. A Detection Agent proposes candidate alerts with local SHAP explanations, while an independent Verification Agent scrutinizes the hypothesis via rules, baselines, anomaly scores, and semantic explainability before generating an evidence report.

Detection Agent
Proposes Hypotheses
• Ingests normalized network flows.
• Supervised ensemble (Random Forest / XGBoost).
• Outputs class + raw probability p_d.
• Generates local SHAP feature attributions.
Verification Agent
Scrutinizes & Filters
• Independent adversarial critic.
• Checks 4 orthogonal corroboration signals.
• Audits semantic consistency of top SHAP features.
• Issues CONFIRM, REDUCE, or REJECT.
Confidence Engine
Stratifies Priority
• Fuses detection & verification scores.
• Computes C = α·p_d + β·p_v + γ·r_corr.
• Maps into High, Medium, Low severity bands.
• Enables prioritized analyst triage.
SOC Dashboard
Actionable Triage
• Real-time confidence-coded alert stream.
• Full JSON & PDF audit report per alert.
• Traceable link: Raw flow → SHAP → Decision.
• Filter by status, attack class, and time.

Literature Survey: ML Intrusion Detection & Benchmark Datasets
Buczak & Guven (IEEE COMST 2016)
Survey of Data Mining & ML Methods for Cybersecurity Intrusion Detection
• Comprehensive taxonomy of classical ML algorithms (Decision Trees, SVM, Naïve Bayes, Clustering).
• Key Finding: High benchmark accuracy does not translate to real-world SOC deployment; identified false positive rate (FPR) as primary operational bottleneck.
• Relevance: Confirms the fundamental limit of standalone classifiers without secondary verification.
Khraisat et al. (Cybersecurity 2019)
Survey of Intrusion Detection Systems: Techniques, Datasets and Challenges
• Examines evolution of signature vs. anomaly-based IDS, current benchmarks, and open challenges.
• Key Finding: Evolving attack diversity, dataset quality, and unacceptably high false alarm rates remain unresolved.
• Relevance: Directly motivates TRUST-SOC's independent verification layer as a filter for false alarms.
Sharafaldin, Lashkari & Ghorbani (ICISSP 2018)
Toward Generating a New Intrusion Detection Dataset (CICIDS2017 & CSE-CIC-IDS2018)
• Created CICIDS2017 to replace stale KDD'99/NSL-KDD; captures 5 days of realistic traffic across 11 attack classes.
• Scaled to CSE-CIC-IDS2018 (AWS enterprise emulation, 450 machines, 80+ CICFlowMeter features).
• Relevance: Selected as primary (CICIDS2017) and cross-validation (CSE-CIC-IDS2018) datasets.
Panigrahi & Borah (IJET 2018)
A Detailed Analysis of CICIDS2017 Dataset for Designing Intrusion Detection Systems
• Rigorous empirical audit identifying label inconsistencies, missing values, infinite packet metrics, and severe class skews.
• Key Finding: Classifiers trained uncritically suffer from severe metric inflation.
• Relevance: Directly guides our data preprocessing pipeline and justifies why raw model outputs must be verified.

Literature Survey: Explainable AI & Multi-Agent Triage
Lundberg & Lee (NeurIPS 2017)
A Unified Approach to Interpreting Model Predictions (SHAP)
• Introduced SHAP (SHapley Additive exPlanations), assigning game-theoretic feature attributions to individual predictions.
• TreeSHAP enables exact, polynomial-time feature importance calculation for ensemble tree models.
• Relevance: Mathematical basis for Detection Agent explanations and Verification Agent consistency checks.
Wang et al. (IEEE Access 2020)
An Explainable Machine Learning Framework for Intrusion Detection Systems
• Evaluated SHAP and LIME feature-attribution specifically on network intrusion detection classifiers.
• Key Finding: Providing feature-level explanations materially accelerates analyst triage and calibrated trust.
• Relevance: TRUST-SOC operationalizes SHAP programmatically as an automated verification signal.
Wei et al. (arXiv 2025) — CORTEX
Collaborative LLM Agents for High-Stakes Alert Triage
• Multi-agent LLM system decomposing triage across behavioral-analysis, evidence-gathering, and reasoning agents.
• Demonstrated substantial false-positive reduction and superior investigation quality over monolithic models.
• Relevance: Architectural precedent proving that an independent verification agent drastically cuts false alarms.
Ameen et al. (2026) & AI-SOC Surveys
QASecClaw: Multi-Agent FP Reduction & AI-Augmented SOC Surveys
• QASecClaw achieved an 88.6% false-positive reduction via dedicated Validation and Evidence-Correlation agents.
• Surveys (Big Data Cogn. Comput. 2025) confirm alert triage, log summarization, and reporting are prime agentic targets.
• Relevance: Confirms multi-agent security triage effectiveness while highlighting the need for reproducible, cost-effective models.

Research Gap: Bridging the Divide in SOC Automation
Silo 1: Academic Benchmark IDS ([1]-[6], [10])
• Single Standalone Model: Focuses strictly on static test-set accuracy of a single classifier without self-questioning.
• Zero In-Flight Verification: Errors pass directly to alerts; false-positive burden is never reduced in the pipeline.
• Passive Visual Explanations: SHAP/LIME used purely for static human charts, never utilized as a machine decision signal.
• No SOC Interface: Research rarely ships with a functional dashboard or exportable evidence-linked audit trails.
Silo 2: Production Multi-Agent LLM SOCs ([7]-[9])
• High API Cost & Latency: Built on commercial large-scale LLMs (GPT-4/Claude) requiring continuous paid API tokens.
• Tethered to Enterprise Logs: Evaluated only on closed, proprietary SIEM data; non-reproducible for academic research.
• Overkill for Flow Triage: Complex prompt chains introduce hallucination risks and high response latencies.
• Inaccessible Implementation: Prohibitive complexity makes them impossible to replicate in a semester micro-project.
THE RESEARCH GAP ADDRESSED BY TRUST-SOC

There is currently NO lightweight, fully reproducible detect-then-verify pipeline that: (1) Is grounded in standardized, open benchmark datasets (CICIDS2017 / CSE-CIC-IDS2018) rather than proprietary enterprise logs; (2) Couples a classical ML Detection Agent with a rule-, baseline-, and explainability-driven Verification Agent instead of costly LLM APIs; (3) Computes a principled, multi-source composite confidence score (C) rather than relying on a raw classifier probability; and (4) Generates an evidence-linked audit report (JSON/PDF) and surfaces the alert stream on a working SOC dashboard within a semester scope.

Verification Agent: 4 Corroboration Signals
(a) Rule / Context Corroboration (r): Cross-checks destination asset criticality, service whitelist, and MITRE ATT&CK technique pattern match.
(b) Statistical Anomaly Corroboration (s): Re-scores flow with an independent unsupervised Isolation Forest trained on benign traffic.
(c) Host/IP Behavioral-Baseline Check (b): Evaluates rolling traffic (packet rate, byte volume, connection bursts) against historical profile.
(d) SHAP Explanation-Consistency Check (e): Confirms top SHAP features match the attack semantics (e.g. packet rate/duration for DDoS).
Decision Rules, Confidence Fusion & Progress
CONFIRM (p_v ≥ 0.70): Alert retained at full strength; escalated for priority scoring.
REDUCE (0.40 ≤ p_v < 0.70): Confidence down-weighted; flagged 'Suspicious - Needs Review'.
REJECT (p_v < 0.40 or ≥2 conflicts): Filtered as verified False Positive; logged to audit.
Score Fusion: C = α·p_d + β·p_v + γ·r_corr  (α=0.4, β=0.4, γ=0.2)
Progress: CICIDS2017 & CSE-CIC-IDS2018 cleaned; 6 threat categories active; Dual reporting + SOC UI wired.
